# 全体レビュー記録（2026-09-18）

対象: 編集・履歴・保存・取得・認証待機・更新サービス・Windowsランチャーと更新スクリプト・CI。

## 修正した問題

- 文章編集のUndoで子要素のリンク・装飾が失われる: 編集前後の内部HTMLを履歴へ記録し復元。旧履歴のテキストのみの形式とも互換を維持。
- body直属要素の複製・削除を戻すための親IDが不安定: bodyにも初期IDを割り当てる。
- 新しいHTMLや案件への切り替えで未保存編集が失われる: 保存済み案件ページは自動保存、それ以外は続行確認。
- 履歴消去やリセットで未保存表示・終了警告が消える: 履歴件数ではなく保存状態で判定。ZIPダウンロードと案件保存を区別して表示。
- 外部WebサイトからローカルAPIへ要求を送れる: Host、Origin、Fetch Metadata、JSON Content-Typeを確認。設定APIで更新ファイル情報を書き換えることも禁止。
- 更新対象に完全版や他OSのZIPが選ばれる: Windows x64更新専用ZIPのみ選択。
- 更新タグによる保存先パス逸脱、検証情報なしの更新: バージョン形式とSHA-256情報を必須検証。
- ダウンロード先の書込失敗が未処理となる: ストリーム処理で例外と後始末を統一。
- 取得用プロファイルの同時利用、終了済みブラウザの残留: ブラウザ操作APIを排他し、ブラウザ終了時にセッションを除去。
- Release入力がPowerShellのコードへ直接埋め込まれる: タグとリリース説明は環境変数で渡す。

## 検証と限界

Node単体テストとChromium操作/APIテストを実施。本番ビルドと差分チェックも実施。新しい回帰ケースは入れ子HTMLのUndo、未保存読込の中止、履歴消去後の未保存表示、外部Origin/非JSON拒否、設定APIの許可項目、更新ZIP種類・ハッシュ情報・不正タグの拒否。

このレビューは全入力・全サイトに対する保証や第三者のセキュリティ監査ではない。以下は残る検証・改善項目。

- Windows更新・ロールバックの実機試験。現状のReleaseスモークテストは同梱Nodeによるサーバー起動であり、ランチャーと更新の全工程試験ではない。
- 案件保存中の障害に対する複数ファイルの一括整合性、外部変更・大量データの試験。
- 実サイトSSO/MFA、期限切れ、sessionStorage依存認証の引き継ぎ。ログイン完了は利用者確認。
- 文章を編集欄で置き換える操作は子要素を平文に置換する。今回の修正はUndoによる復元を保証するもので、置換時の部分装飾保持ではない。
- ブラウザネイティブの文字編集Undoとアプリの操作履歴の統合、複製時の元HTMLのid重複。
- 元HTMLはアクティブなコンテンツを含み得る。編集プレビューのsandboxは、出力HTMLを外部ブラウザで開いた際の安全性を保証しない。

GitHubへのmainプッシュのみ実施し、新しいRelease公開やバージョンタグ追加は行わない。
