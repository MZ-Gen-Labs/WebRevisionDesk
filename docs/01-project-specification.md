# Webサイト修正指示作成ツール プロジェクト全体仕様書

- 文書種別: プロジェクト概要・MVP仕様
- ステータス: Pilot Ready 1.2
- 対象: 社内利用
- 作成日: 2026-09-17
- 更新日: 2026-09-18

## 1. プロジェクト概要

### 1.1 名称

Webサイト修正指示作成ツール（製品名: Web Revision Desk）

### 1.2 要約

既存Webページを見たまま編集し、その操作内容から修正前、修正後、赤入れ差分、修正指示一覧を生成する。Webサイト制作ツールではなく、修正案の作成と業務部門への修正指示作成を一体化する社内ツールである。

## 2. 背景と課題

現在のWebサイト更新は業務部門が担当しており、依頼者は修正箇所、変更内容、完成イメージをPowerPoint、Word、メール、注釈付きスクリーンショット等で説明している。この方法には次の課題がある。

- 指示書の作成に時間がかかる
- 修正後の完成像が伝わりにくい
- 文章、画像、リンク、配置変更を別々に説明する必要がある
- 修正前後の資料が分散する
- 変更箇所の見落としや認識齟齬が発生する

## 3. 目的

既存ページそのものを修正案の土台にし、次の業務フローを実現する。

```text
現在のWebページ
  → SingleFileまたは内蔵URL取得で単一HTMLとして保存
  → ページを画面上で直接編集
  → 変更内容を記録・比較
  → 修正前・修正後・差分・変更一覧を生成
  → 業務部門へ修正指示として提出
```

## 4. 想定利用者

- Webサイト修正を依頼する社員
- HTML/CSSの専門知識を持たない企画・確認担当者
- 修正内容を業務部門へ正確に伝える必要がある担当者

Web制作担当者向けの汎用オーサリングツールは目指さない。

## 5. 基本方針

1. 既存ページの表示と構造を可能な限り維持する。
2. 利用者にHTML、CSS、JavaScriptの直接編集を要求しない。
3. CSSコードは作成せず、元ページに存在するclassを再利用する。
4. 元HTMLは不変のスナップショットとして保持する。
5. 本番サイト、CMS、サーバーへは接続しない。
6. 入力HTMLは信頼せず、編集プレビューではスクリプト実行を禁止する。

## 6. 対象業務フロー

### 現状

```text
ページ確認 → スクリーンショット取得 → 指示文章作成
→ 修正位置と前後内容を説明 → 業務部門へ送付 → 結果確認
```

### 目標

```text
ページ保存 → HTML読込 → ページ上で修正案を作成
→ 修正指示を自動生成 → 業務部門へ提出
```

## 7. 採用・候補ツール

| 領域 | ツール/方式 | 方針 |
|---|---|---|
| ページ保存 | SingleFile | 任意の外部取得手段として出力HTMLの読込に対応。コードは組み込まない |
| 内蔵ページ取得 | Playwright + 独自埋め込み処理 | 採用。商用利用可能なApache-2.0ライセンス |
| PoC編集 | iframe + contenteditable + DOM API | 採用。標準APIで限定編集する |
| 汎用編集 | VvvebJs | 将来候補。PoCでは不採用 |
| テキスト差分 | htmldiff.js系 | MVP-06で再評価 |
| DOM差分 | 操作履歴、必要に応じdiffDOM | ライセンスを確認して再評価 |
| ブラウザ自動操作 | Playwright | URL取得用Chromiumの起動に採用 |

SingleFileは利用可能な取得手段の一つであり、拡張機能の導入が難しい環境では内蔵ページ取得を使用する。SingleFileのプログラムコードはシステムへ組み込まない。

## 8. MVP機能

### MVP-01 既存ページの取り込み

- SingleFile等で保存した `.html` をローカルから選択する
- URLを取得用ブラウザで開き、表示中ページを単一HTMLとして取り込む
- 基準URLと同一ドメイン・配下パスのページを再帰検索して重複なく一覧化する
- 未取得ページを一覧から選び、取得用ブラウザで確認後に取り込む
- 複数ページを選択し、同じログイン状態で順番に一括取得する
- 保存済みページと公開中ページのテキスト、リンク、画像、構造、CSSを比較する
- 更新確認では自動上書きせず、現状維持または旧版バックアップ後の更新を選択する
- CSS、画像、フォント等が埋め込まれたHTMLを表示する
- 読込直後の文字列を `originalHtml` として不変保持する

### MVP-02 ページ上で直接編集

- テキスト変更
- リンクURL変更
- 画像差し替え、alt変更
- 要素削除
- 要素複製
- 同一親要素内で前後移動
- 既存ブロックの複製による要素追加

### MVP-03 既存デザインの利用

- 元ページに存在するclass名を抽出する
- 選択要素のclassを追加・削除する
- CSSプロパティの自由入力は提供しない

### MVP-04 修正前・修正後の保持

- `originalHtml` と `modifiedHtml` を明確に分離する
- 修正前/修正後の表示を切り替える
- Undo/Redoで編集操作を段階的に戻す・やり直す
- すべてリセットで読込直後へ復元する
- `modified.html` をダウンロードする
- 案件一式をZIPでダウンロードする
- `original.html`、`modified.html`、差分、赤入れ、案件情報をZIPへ同時出力する

### MVP-05 変更履歴

次の操作をイベントとして記録する。

- `text-change`
- `image-change`
- `link-change`
- `class-change`
- `element-add`
- `element-delete`
- `element-move`

### MVP-06 差分HTML

- 削除文を `<del>`、追加文を `<ins>` で表示する
- 属性、画像、要素追加・削除・移動も判別できる形を検討する

### MVP-07 修正指示一覧

変更履歴から、対象、変更種別、変更前、変更後、位置を自動一覧化する。

### MVP-08 修正指示ページ

対象URL、対象ページ、作成日、修正前、修正後、赤入れ差分、変更一覧を1ページに統合し、HTMLまたはPDFとして出力する。

## 9. 画面構成

```text
┌─────────────────────────────────────────────┐
│ HTML読込 | 修正前後 | Undo/Redo | 共有用一式保存 │
├─────────────────────────────────────────────┤
│ ①ページを取り込む → ②修正する → ③確認して保存 │
├──────────┬─────────────────────┬────────────┤
│ページ一覧 │ 既存Webページ       │ 編集メニュー│
│案件管理   │ クリックして選択     │ 必要項目のみ│
│一括取得   │ ダブルクリック編集   │ 詳細設定    │
└──────────┴─────────────────────┴────────────┘
```

初心者には現在の操作段階、選択対象に応じた説明、必要な編集項目だけを表示する。altとCSS classは「詳細設定」にまとめる。従来のダブルクリック編集とキーボードショートカットは、習熟者向けの高速操作として維持する。保存状態は「変更なし」「未保存の変更あり」「保存済み」で表示し、未保存の変更がある状態で終了する場合は警告する。

## 10. 非機能要件

### 10.1 対応環境

- Windows 11を主対象とする
- Chrome / Edgeの現行安定版を対象とする
- ローカルWebアプリとして動作する

### 10.2 セキュリティ

- 入力HTMLを信頼しない
- iframeのsandboxでスクリプト、フォーム、ポップアップ、トップ遷移を許可しない
- プレビューに必要な同一オリジンDOMアクセスのみ許可する
- サーバー送信や外部保存を行わない
- SingleFile以外のHTMLに外部リソースが含まれる場合、表示時に通信が発生し得ることを明示する

### 10.3 データ保持

- 単一ページ作業はブラウザメモリ内で保持する
- 正式運用向けには利用者が選択した案件フォルダへ複数ページを保存する
- `project.json` とURL相当の相対フォルダでページを管理する
- OS依存の絶対パスは保存しない
- ページ切替時は未保存ページを自動保存する

### 10.4 互換性

- HTMLのブラウザ再解析・再直列化により、属性順序、空白、暗黙タグ等は変化し得る
- 見た目と意味の保持を優先し、バイト単位の同一性は保証しない
- Canvas、Shadow DOM、クロスオリジンiframe、動的JavaScript依存表示は保証対象外とする

### 10.5 配布・更新

- Windows 11向けにはNode.js、依存モジュール、取得用Chromiumを含むポータブルZIPを生成する
- アプリ本体の外に設定と取得用ブラウザプロファイルを保持し、ZIP更新後も引き継ぐ
- GitHub Releasesから更新版とセキュリティ更新情報を確認する
- 更新版は別フォルダへ展開して切り替え、起動確認に失敗した場合は旧版へ戻す
- 開発版とmacOS版では自動切り替えを無効とし、配布形態の確定後に個別対応する

## 11. MVP対象外

- CSSコード編集、JavaScript編集
- 新規サイト制作、高度なドラッグ&ドロップ、自由配置
- レスポンシブデザイン制作
- CMS、WordPress、FTP、本番環境との連携
- ログイン、ユーザー管理、データベース
- 複数ユーザー共同編集、Git連携
- 元のReact/Vue等のソースプロジェクト復元

## 12. 成功指標

主要指標は修正指示作成時間の削減率とする。副次指標は、変更見落とし、認識齟齬、手戻り件数、利用者がHTML/CSSを直接触る回数とする。

## 13. 段階計画

1. PoC: MVP-01〜06の主要機能と内蔵URL取得の技術成立性を確認（完了）
2. Pilot: 複数の実ページによる互換性・運用・安全性検証
3. MVP: 案件保存、Undo/Redo、初心者向け操作案内（実装済み）、修正指示ページの仕上げ
4. 運用評価: 作業時間と手戻りを測定し正式導入を判断

## 14. 未決事項

- 対象サイトで使用されるSingleFile保存設定の標準化
- 外部通信を完全遮断する運用要件
- class候補の全件表示と使用中classのみ表示の選択
- 操作履歴ベースとDOM差分ベースの責任分界
- 社内配布方式（静的ファイル、デスクトップ包装、社内Web配信）
