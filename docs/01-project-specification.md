# Webサイト修正指示作成ツール プロジェクト全体仕様書

- 文書種別: プロジェクト概要・MVP仕様
- ステータス: Pilot Ready 1.3（Electron版 v0.6.4）
- 対象: 社内利用を想定したOSS
- 作成日: 2026-09-17
- 更新日: 2026-09-21

## 1. プロジェクト概要

### 1.1 名称

Webサイト修正指示作成ツール（製品名: Web Revision Desk）

### 1.2 要約

既存Webページを見たまま編集し、その操作内容から修正前、修正後、赤入れ差分、修正指示一覧を生成する。Webサイト制作ツールではなく、修正案の作成と業務部門への修正指示作成を一体化する社内ツールである。

## 2. 背景と課題

現在のWebサイト更新は業務部門が担当しており、依頼者は修正箇所、変更内容、完成イメージをPowerPoint、Word、メール、注釈付きスクリーンショット等で説明している。この方法には次の課題がある。

- 指示書の作成に時間がかかる
- 修正後の完成像が伝わりにくい
- 文章、画像、リンク、配置変更を別々に説明する必要がある
- 修正前後の資料が分散する
- 変更箇所の見落としや認識齟齬が発生する

## 3. 目的

既存ページそのものを修正案の土台にし、次の業務フローを実現する。

```text
現在のWebページ
  → Electron内蔵Chromiumまたは保存済みHTMLから単一HTMLとして保存
  → ページを画面上で直接編集
  → 変更内容を記録・比較
  → 修正前・修正後・差分・変更一覧を生成
  → 業務部門へ修正指示として提出
```

## 4. 想定利用者

- Webサイト修正を依頼する社員
- HTML/CSSの専門知識を持たない企画・確認担当者
- 修正内容を業務部門へ正確に伝える必要がある担当者

Web制作担当者向けの汎用オーサリングツールは目指さない。

## 5. 基本方針

1. 既存ページの表示と構造を可能な限り維持する。
2. 利用者にHTML、CSS、JavaScriptの直接編集を要求しない。
3. CSSコードは作成せず、元ページに存在するclassを再利用する。
4. 元HTMLは不変のスナップショットとして保持する。
5. 本番サイト、CMS、サーバーへは接続しない。
6. 入力HTMLは信頼せず、編集プレビューではスクリプト実行を禁止する。

## 6. 対象業務フロー

### 現状

```text
ページ確認 → スクリーンショット取得 → 指示文章作成
→ 修正位置と前後内容を説明 → 業務部門へ送付 → 結果確認
```

### 目標

```text
ページ保存 → HTML読込 → ページ上で修正案を作成
→ 修正指示を自動生成 → 業務部門へ提出
```

## 7. 採用・候補ツール

| 領域 | ツール/方式 | 方針 |
|---|---|---|
| ページ保存 | SingleFile | 任意の外部取得手段として出力HTMLの読込に対応。コードは組み込まない |
| 内蔵ページ取得 | Electron内蔵Chromium + 独自埋め込み処理 | 採用。Playwrightや外部ブラウザに依存しない |
| PoC編集 | iframe + contenteditable + DOM API | 採用。標準APIで限定編集する |
| 汎用編集 | VvvebJs | 将来候補。PoCでは不採用 |
| テキスト差分 | 独自の変更履歴・赤入れ生成 | 採用。外部差分ライブラリを使わない |
| DOM差分 | 操作履歴を正本にし、表示用赤入れを生成 | 採用。汎用DOM差分は将来再評価 |
| 認証・取得操作 | Electron内の専用セッション | 採用。利用者がログイン完了を明示する |

SingleFileは利用可能な補助的取得手段であり、プログラムコードは組み込まない。標準運用ではElectron内蔵Chromiumで、表示済みページのCSS・画像等を可能な限り埋め込んだHTMLを取得する。

## 8. MVP機能

### MVP-01 既存ページの取り込み

- 案件単位の「ログインが必要」設定と、利用者のログイン完了を待つ専用操作を提供する（詳細と制約はREADME参照）

- SingleFile等で保存した `.html` をローカルから選択する
- URLを取得用ブラウザで開き、表示中ページを単一HTMLとして取り込む
- 一覧にないURLは案件設定から未取得ページとして追加し、以後は一覧上でプレビュー・取り込みを行う
- 基準URLと同一ドメイン・配下パスのページを再帰検索して重複なく一覧化する
- 未取得ページを一覧から選ぶと、案件へ保存せず中央に画面上部のスクリーンショットを表示する。利用者が取り込みを実行した時点で完全なHTMLを取得し、保存・編集可能にする。ログインや表示調整が必要な場合は取得用ブラウザも選べる
- 選択した保存済みページをリセットし、URL候補を残したまま原本・修正後・差分・履歴・旧版を削除して未取得へ戻す
- 複数ページを選択し、同じログイン状態で順番に一括取得する
- 保存済みページと公開中ページのテキスト、リンク、画像、構造、CSSを比較する
- 更新確認では自動上書きせず、現状維持または旧版バックアップ後の更新を選択する
- CSS、画像、フォント等が埋め込まれたHTMLを表示する
- 読込直後の文字列を `originalHtml` として不変保持する

### MVP-02 ページ上で直接編集

- テキスト変更
- リンクURL変更、文章内リンクの設定・解除
- 画像差し替え、画像URL・alt・リンク先変更、差し替え元ファイル名の保持
- 要素削除
- 要素コピーと、選択位置の前後への貼付け
- 同一親要素内で前後移動
- 親要素選択と子要素への復帰、Ctrl/Cmd追加選択、Shift範囲選択
- 表の追加、セル文章編集、行・列の追加・削除、表全体の削除

### MVP-03 既存デザインの利用

- 元ページに存在するclass名を抽出する
- 選択要素のclassを追加・削除する
- CSSプロパティの自由入力は提供しない

### MVP-04 修正前・修正後の保持

- `originalHtml` と `modifiedHtml` を明確に分離する
- 修正前/修正後/変更箇所の表示を切り替える。変更箇所では赤入れHTMLを中央画面へ参照専用で表示する
- Undo/Redoで編集操作を段階的に戻す・やり直す
- すべてリセットで読込直後へ復元する
- ページ一覧で複数選択されている場合は、対象ページだけの編集内容・履歴を一括リセットする
- 案件ページは編集・ページ切替・アプリ終了時に自動保存する
- `modified.html` をダウンロードする
- 案件一式をZIPでダウンロードする
- `original.html`、`modified.html`、差分、赤入れ、案件情報をZIPへ同時出力する

### MVP-05 変更履歴

次の操作をイベントとして記録する。

- `text-change`
- `image-change`
- `link-change`
- `class-change`
- `element-add`
- `element-delete`
- `element-move`
- `inline-link-change`、`image-link-change`、`alt-change`
- `meta-title-change`、`meta-description-change`、`table-change`

### MVP-06 差分HTML

- 削除文を `<del>`、追加文を `<ins>` で表示する
- 属性、画像、要素追加・削除・移動、表構成変更をラベル付きで表示する
- 画像変更は旧画像・新画像と、変更後画像を元ファイル名で取得できる導線を表示する

### MVP-07 修正指示一覧

変更履歴から、対象、変更種別、変更前、変更後、位置を自動一覧化する。

### MVP-08 修正指示ページ

対象URL、対象ページ、作成日、修正前、修正後、赤入れ差分、変更一覧をHTMLとして出力する。PDF化はブラウザ印刷または後続機能とする。

## 9. 画面構成

```text
┌─────────────────────────────────────────────┐
│ 修正前・修正後・変更箇所 | Undo/Redo | 保存   │
├──────────┬─────────────────────┬────────────┤
│ページ一覧 │ 既存Webページ       │ 編集メニュー│
│案件管理   │ クリックして選択     │ 必要項目のみ│
│一括取得   │ ダブルクリック編集   │ 詳細設定    │
└──────────┴─────────────────────┴────────────┘
```

初心者には選択対象に応じた説明と必要な編集項目だけを表示する。alt、CSS class、表の新規作成は「詳細設定」にまとめるが、表・行・セルを選択した間は表編集メニューを自動表示する。従来のダブルクリック編集とキーボードショートカットは、習熟者向けの高速操作として維持する。案件ページは編集後に自動保存し、「自動保存待ち」「自動保存中」「自動保存済み」で状態を表示する。ダウンロードと案件保存は区別する。

## 10. 非機能要件

### 10.1 対応環境

- Windows 11を主対象とする
- Electron版を標準配布とする
- Windows 11向けポータブルZIPを主対象とし、macOS開発環境でも動作確認する

### 10.2 セキュリティ

- 入力HTMLを信頼しない
- iframeのsandboxでスクリプト、フォーム、ポップアップ、トップ遷移を許可しない
- プレビューに必要な同一オリジンDOMアクセスのみ許可する
- サーバー送信や外部保存を行わない
- SingleFile以外のHTMLに外部リソースが含まれる場合、表示時に通信が発生し得ることを明示する

### 10.3 データ保持

- 単一ページ作業はブラウザメモリ内で保持する
- 正式運用向けには利用者が選択した案件フォルダへ複数ページを保存する
- `project.json` とURL相当の相対フォルダでページを管理する
- OS依存の絶対パスは保存しない
- ページ切替時は未保存ページを自動保存する
- Redlineの変更後画像は、保持した元ファイル名で直接ダウンロードできる

### 10.4 互換性

- HTMLのブラウザ再解析・再直列化により、属性順序、空白、暗黙タグ等は変化し得る
- 見た目と意味の保持を優先し、バイト単位の同一性は保証しない
- Canvas、Shadow DOM、クロスオリジンiframe、動的JavaScript依存表示は保証対象外とする

### 10.5 配布・更新

- Windows 11向けにはElectronランタイムと依存モジュールを含むポータブルZIPを生成する。利用端末へのNode.js導入は不要とする
- アプリ本体の外に設定とElectron取得セッションのプロファイルを保持し、ZIP更新後も引き継ぐ
- GitHub Releasesから更新版とセキュリティ更新情報を確認する
- 更新版は別フォルダへ展開して切り替え、起動確認に失敗した場合は旧版へ戻す
- 開発版とmacOS版では自動切り替えを無効とし、配布形態の確定後に個別対応する

## 11. MVP対象外

- CSSコード編集、JavaScript編集
- 新規サイト制作、高度なドラッグ&ドロップ、自由配置
- レスポンシブデザイン制作
- CMS、WordPress、FTP、本番環境との連携
- ログイン、ユーザー管理、データベース
- 複数ユーザー共同編集、Git連携
- 元のReact/Vue等のソースプロジェクト復元

## 12. 成功指標

主要指標は修正指示作成時間の削減率とする。副次指標は、変更見落とし、認識齟齬、手戻り件数、利用者がHTML/CSSを直接触る回数とする。

## 13. 段階計画

1. PoC: MVP-01〜06の主要機能と内蔵URL取得の技術成立性を確認（完了）
2. Pilot: Electron移行、案件フォルダ管理、複数ページ取得・更新確認、初心者向け編集を実装（完了）
3. 運用評価: 複数の実ページによる互換性・操作性・安全性を検証する（進行中）
4. 正式導入判断: 作業時間と手戻りを測定し、配布・更新運用を確定する

## 14. 未決事項

- 実サイトごとの取得不能リソース、動的表示、ログイン状態の互換性
- 外部通信を完全遮断する必要がある案件の運用要件
- class候補の全件表示と使用中classのみ表示の選択
- 操作履歴ベースとDOM差分ベースの責任分界
- Windows配布ZIPの署名、社内配布・更新ルール
