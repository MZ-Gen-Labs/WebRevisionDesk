# Web Revision Editor Pilot・実運用移行計画

- ステータス: Draft 1.0
- 作成日: 2026-09-17
- 前提: PoC主要機能の動作確認完了

## 1. PoC確認結果

以下は実装済みで、基本動作を確認済みである。

- SingleFile HTMLとURLから取得したHTMLの読み込み
- CSS、CSS内 `@import`、画像を含む主要レイアウトの再現
- テキスト、リンク、画像、alt、classの編集
- 要素の削除、前後移動、既存ブロックの複製
- 修正前・修正後の保持、読込時点へのリセット
- 修正後HTML、操作差分HTML、赤入れHTMLの保存

技術方式は `iframe + contenteditable + DOM API` を継続採用する。現時点ではVvvebJsへ移行する必要性は低い。

## 2. Pilotの目的

実際の修正依頼業務で試し、対応可能なページ範囲、作業時間削減、指示の伝わりやすさ、安全な運用方法を確定する。

## 3. 優先順位

### P0: Pilot開始前に必要

1. 案件一式の保存（実装済み）
   - original.html、modified.html、差分HTML、赤入れHTMLを同じ案件として出力する
   - 対象URL、ページ名、作成日時を含む
2. Undo/Redo（実装済み）
   - 直前操作を段階的に戻す・やり直す
   - 現在の「元に戻す」は全変更リセットとして名称を分ける
3. エラー表示
   - 取得できなかったCSS・画像・フォントを一覧化する
   - 取得失敗と編集失敗を区別する
4. 取得・保存テスト
   - 実ページ5〜10件で原本、取得結果、保存結果を比較する
5. 利用上の注意
   - 社外秘・個人情報を含むページの扱い
   - 取得権限と著作権を持つページだけを対象とする

### P1: Pilot中に改善

1. 案件フォルダによる複数ページ保存・作業再開（初期実装済み）
2. 基準URL配下の再帰検索、重複除外、未取得ページから取得ブラウザを開く操作（実装済み）
3. 複数選択、一括取得、公開ページ更新確認、バックアップ付き更新（実装済み）
4. 変更履歴の編集、並べ替え、注記追加
5. 選択要素の階層表示と選択しやすさの改善
6. 複製したブロック内のID重複警告
7. ページ取得の未取得リソース表示
8. 修正指示ページの印刷・PDF向けレイアウト

### P2: 正式導入時に判断

1. デスクトップアプリ化または社内配布パッケージ化
2. 複数ページ案件の選択エクスポート
3. テンプレート化したブロック追加
4. 承認フロー、共同編集、CMS連携

## 4. 互換性の境界

次の内容は静的な取得・編集との相性が悪く、保証対象外または個別検証とする。

- canvas描画、動画プレイヤー、地図等の動的コンテンツ
- Shadow DOM、クロスオリジンiframe内部
- JavaScript実行後も継続的に更新される画面
- ログイン期限やアクセス制御で取得できないリソース
- CSS疑似要素内の文言、CSS背景画像の専用編集
- 保存時点より後の操作で初めて読み込まれる遅延コンテンツ

## 5. Pilot評価指標

各案件で次を記録する。

| 指標 | 測定内容 |
|---|---|
| 作成時間 | 従来の指示書と本ツールの所要時間 |
| 再現性 | 重大なレイアウト崩れの有無 |
| 網羅性 | 意図した変更が差分へすべて出たか |
| 理解度 | 実装担当者が追加確認なしで理解できたか |
| 手戻り | 修正漏れ、誤解、再依頼の件数 |
| 操作性 | 利用者が迷った操作と所要時間 |

## 6. Pilot合格基準案

- 対象ページの80%以上で重大なレイアウト崩れがない
- 主要な変更操作の95%以上が差分へ記録される
- 修正指示作成時間が従来比30%以上短縮される
- 実装担当者による変更箇所の見落としが発生しない
- 重大なセキュリティ事故またはデータ消失がない

## 7. 推奨する次の実装単位

「案件一式をZIPで保存」「Undo/Redo」「案件フォルダ管理」「配下ページ検索」「複数ページの一括取得」「公開ページ更新確認」「バックアップ付き更新」は実装済み。次は複数ページの選択ZIP出力、実ページ互換性試験、取得できなかったリソースの可視化を行う。
