# Web Revision Desk

既存Webページを取り込み、見た目を確認しながら編集し、修正後HTML、視覚的な赤入れ、修正指示を作成するデスクトップ向けローカルWebアプリです。

[![CI](https://github.com/MZ-Gen-Labs/WebRevisionDesk/actions/workflows/ci.yml/badge.svg)](https://github.com/MZ-Gen-Labs/WebRevisionDesk/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

SingleFileを使わず、URLをElectron内蔵Chromiumで開いて現在の表示を単一HTMLとして取り込めます。外部ブラウザ、Playwright、localhost APIを必要としません。

## Electron版

v0.6.0以降はElectron版が標準です。Electron内蔵Chromiumでページ検索・プレビュー・取り込みを行い、案件フォルダはOS標準のフォルダ選択画面から利用します。

```bash
npm ci
npm run electron:dev
```

元の機能検証画面は`npm run electron:feasibility`で残しています。検証結果は[`docs/05-electron-feasibility.md`](docs/05-electron-feasibility.md)、移行内容は[`docs/06-electron-migration.md`](docs/06-electron-migration.md)を参照してください。

## できること

- ローカルHTMLの読込とsandbox内プレビュー
- ページ内要素の選択、テキスト編集
- リンクURL、画像、alt、CSS classの変更
- 要素の削除と同一親内での前後移動
- 選択した既存ブロックの複製
- 編集操作の変更履歴表示
- 変更前後をまとめた差分・修正指示HTMLの出力
- 元ページの見た目に取消し線・追加色・変更ラベルを重ねた赤入れHTMLの出力
- 修正前/修正後/変更箇所の切替と読込時点へのリセット
- 操作単位のUndo/Redo（ボタンおよびCtrl/Cmd+Z）
- `modified.html` のダウンロード
- 修正前・修正後・差分・赤入れ・案件情報のZIP一括保存
- 基準URL配下の複数ページを案件フォルダで階層管理
- 選択した要素に必要な項目だけを表示する初心者向け編集メニュー
- 未保存状態の表示と、未保存のまま画面を閉じる際の警告

## 起動方法

利用者はGitHub ReleasesからWindows ZIPを取得し、展開後に`Start-WebRevisionDesk.cmd`を実行します。

ソースから起動する場合はNode.js 20以降を用意し、次を実行します。

```bash
npm ci
npm run electron:dev
```

従来のローカルWeb版は互換性確認用として`npm run dev`で起動できます。

## テスト

依存モジュール更新後を含む通常の確認は、Chromiumをインストールしたうえで次を実行します。

```bash
npx playwright install chromium
npm test
```

`npm test` は、URL階層・Windowsファイル名・更新判定・SHA-256拒否等の単体テスト、本番ビルド、HTML読込・編集・Undo/Redo・ZIP出力・詳細設定のブラウザテストを順に実行します。GitHub ActionsでもPull Requestと`main`へのpushごとに同じ主要テストを実行します。Windows Releaseでは生成したElectron ZIPを展開し、連続取得、取得エラー後の解放、起動を追加確認します。

## バージョンとリリース

`package.json` をアプリのバージョン番号の正本とします。画面表示、Windows ZIP名、`release.json`、更新確認はこの値を使用します。`npm run version:check` は `package.json`、`package-lock.json`、リリース時のGitタグが一致することを検証し、不一致の場合はCIとリリースを停止します。

通常の機能追加版を公開する手順は次のとおりです。

```bash
npm version minor --no-git-tag-version
npm test
git add package.json package-lock.json
git commit -m "Release vX.Y.Z"
git tag -a vX.Y.Z -m "Web Revision Desk vX.Y.Z"
git push origin main
git push origin vX.Y.Z
```

修正のみは `minor` を `patch`、互換性を壊す変更は `major` に置き換えます。タグのpushによりWindows版のビルド、整合性検査、GitHub Release公開が自動実行されます。テストに失敗した場合はタグを作成しません。

## 操作方法

案件選択・ログイン・補助的な取り込みは「取り込み・案件設定」を開いて操作します。ページ読込後はこの設定欄が自動で閉じ、編集領域が画面の残りの高さまで広がります。必要なときは見出しを押して再表示できます。案件保存・修正前後・Undo/Redo・共有用保存は上部に常時表示します。

1. 案件フォルダを選び、左側のページ一覧から対象ページを開く
2. ページ上の直したい要素をクリックする
3. 右側の「編集メニュー」に表示された項目から内容を変更する
4. 文章はページ上でダブルクリックして直接編集することもできる
5. 「修正前」「修正後」「変更箇所」で表示を比較する
6. 「共有用ファイル一式を保存」で提出・保管用ZIPを出力する
7. 修正後ページ、修正内容一覧、変更箇所ページだけが必要な場合は「その他の保存」から選ぶ

「1つ戻す」「やり直す」で編集操作を段階的に戻せます。「すべてリセット」は全変更を読み込み時点へ戻します。
通常は文章・リンク・画像差し替えだけが表示されます。画像のaltやCSS classを変更する場合は「詳細設定を表示」を有効にします。読込・変更後は「案件フォルダへ未保存」と表示され、案件フォルダへ保存すると「保存済み」になります。ZIPやHTMLのダウンロードでは案件フォルダへの保存状態は変わりません。

SingleFile等で保存済みのHTMLを使用する場合は、「取り込み・案件設定」内の「その他の取り込み」を開きます。元のURLを入力して「保存済みHTMLを案件へ追加」を選ぶと、単独編集ではなく現在の案件ページとして保存されます。

## 案件フォルダで複数ページを管理

1. ChromeまたはEdgeで「案件フォルダを選択」を押す
2. 新規または既存の案件フォルダを選択する
3. 案件名と基準URLを入力する
4. 「関連ページを探す」を押す
5. 左側に表示された「未取得」ページを選ぶ
6. ログインや表示調整が必要な場合は、一覧の「取得用ブラウザで開く」から確認し、中央上部の「表示中ページを取り込む」を押す
7. 編集後に「案件フォルダに保存」を押す
8. 「保存済み」になったページは左側一覧から編集状態を再度開ける

一括検索は基準URLと同じドメインかつ配下パスだけを再帰的にたどり、アンカー違い・追跡用クエリ等を正規化して重複を除外します。画像、PDF、動画、ZIP等はページ候補に含めません。1回の検索は最大100ページで停止します。ログインや画面操作が必要なページは、一覧から選んで取得用ブラウザを開いた後に操作できます。

関連ページ検索で見つからないページは、「取り込み・案件設定」内の「その他の取り込み」でURLをページ一覧へ追加できます。URLを追加しただけではHTMLを保存せず、他の未取得ページと同じく画像プレビューから取り込みを判断できます。

基準URLが `https://example.com/products/widget` の場合、ページは次のように保存されます。

```text
案件フォルダ/
├── project.json
└── pages/products/widget/
    ├── index/
    │   ├── original.html
    │   ├── working.html
    │   ├── modified.html
    │   ├── diff.html
    │   ├── redline.html
    │   └── page.json
    └── function_const_01/
        └── ...
```

フォルダ名にはWindows 11で利用可能な文字だけを使用し、`project.json` と `page.json` のパスはOSに依存しない相対パスで記録します。編集途中の状態は `working.html`、提出可能な修正後ページは `modified.html` です。ページを切り替える際は未保存のページを案件フォルダへ自動保存します。

一括検索は、自身または所属組織が取得を許可されているサイトに対して使用してください。

### 一括取得と公開ページの更新確認

- 左側のチェックボックスで複数ページを選択する
- 「選択を一括取得」で未取得ページを順番に取得・保存する
- 未取得ページの本体をクリックすると、スクリーンショット取得後に完全なHTMLを取得し、案件フォルダへ保存して編集可能にする
- 「画像を更新」で公開ページの最新スクリーンショットを取得する。直近の画像は5分間だけメモリへ一時キャッシュされ、案件フォルダには保存しない
- ログインや画面操作が必要なページは、一覧下の「取得用ブラウザで開く」から確認後に取り込む
- 保存済みページを選び「選択を更新確認」で公開中ページとの差を確認する
- 「選択を未取得へ戻す」で、選択した保存済みページの原本・編集内容・差分・履歴・旧版を削除する。URLは一覧に残るため再取得できる
- 緑の「公開版と同じ」は取得時点と同じ状態
- オレンジの「公開版に更新あり」はテキスト、リンク、画像、構造、CSSのいずれかに差がある状態
- 「上書きしない」で案件内の編集を維持する
- 「バックアップして更新」で現在の一式を `versions/` へ退避してから公開版へ置き換える

更新確認だけでは `original.html` や編集中の内容を上書きしません。上書きを選択した場合も旧版はページフォルダ内の `versions/<日時>/` に保存されます。一括処理は同じログインプロファイルを使い、サーバー負荷を抑えるため1ページずつ順番に実行します。リセットは削除確認後に実行され、選択したページ自身の保存ファイルだけを対象とするため、URL階層上の子ページは保持されます。

## URLから取り込む

1. 関連ページ検索、または「その他の取り込み」の「URLをページ一覧へ追加」で対象URLを一覧へ追加する
2. 未取得ページの「取得用ブラウザで開く」を押す
3. 開いたChromiumで必要に応じてログイン、スクロール、タブ展開等を行う
4. 編集画面中央上部の「表示中ページを取り込む」を押す
5. CSS・画像等の埋め込み後、案件フォルダへ自動保存されたページの編集を開始する

通常の一覧クリックでは画像確認からHTML取得まで自動で進みます。JavaScript操作やログイン後の状態を反映して取り込みたい場合に「取得用ブラウザで開く」を使います。

取得用ブラウザのログイン状態はElectronの専用ユーザーデータ領域に保存され、外部サービスへは送信されません。Windowsでは通常`%APPDATA%\WebRevisionDesk`配下です。共有PCでは利用後のプロファイル管理に注意してください。

## アプリの設定と更新確認

### ログインが必要なページの取得準備

案件フォルダを選択して基準URLを入力し、「このサイトはログインが必要」を有効にします。「ログイン用ブラウザを開く」で表示したブラウザ内でログイン・多要素認証を済ませ、対象ページを閲覧できることを確認してから、編集画面の「ログイン完了」を押してください。待機中は関連ページ検索、一括取得、公開ページ更新確認を開始できません。「ログイン待機を中止」で待機を取り消せます。

スイッチは選択中の案件へ保存されます。完了状態は画面を開いている間だけ保持し、案件の切り替えやURLの手入力変更で再確認待ちに戻ります。ログイン成功や期限切れの自動判定は行いません。認証が切れた場合は再度ログイン用ブラウザを開いてください。

完了時にブラウザを閉じ、専用プロファイルに残るCookie等を後続処理で使用します。ブラウザ終了時に失効する認証やsessionStorageのみを使うサイトでは、一括処理に認証を引き継げない場合があります。その場合は取得用ブラウザでログイン後、そのまま「表示中ページを取り込む」を利用してください。待機の中止はログアウトや認証情報の消去ではありません。専用プロファイルは案件間で共通です。

### 更新確認

Electron v0.6.0では自動更新を無効にしています。新しい正式版が公開された場合はGitHub ReleasesからZIPを取得し、既存とは別のフォルダへ展開して切り替えます。案件データは利用者が選択した案件フォルダに保存されるため、新しいアプリフォルダから同じ案件フォルダを選択して継続できます。

## Windows Electron版の作成

Windows 11またはWindowsのCI環境で次を実行します。

```powershell
npm ci
$env:WEB_REVISION_ELECTRON_RELEASE = "1"
npm run build:electron:win
```

`release-electron/` に次が生成されます。

- `WebRevisionDesk-<version>-electron-win-x64.zip`：Windows x64配布用
- `SHA256SUMS.txt`：配布物のSHA-256

ZIPを展開し、`Start-WebRevisionDesk.cmd`を実行すると起動します。GitHub ReleaseにはZIPと`SHA256SUMS.txt`を添付します。

## 安全性と制約

編集プレビューはsandbox付きiframeに表示し、入力HTMLのスクリプト、フォーム送信、ポップアップを許可しません。ページ取り込みではCSS、CSS内の追加CSS、画像等を可能な範囲で単一HTMLへ埋め込みます。取得後も外部URLが残るページでは通信が発生する可能性があります。

ブラウザでHTMLを再解析するため、属性順序や空白等は元ファイルと同一にならない場合があります。iframe、Shadow DOM、canvas、疑似要素、JavaScriptが再生成する内容の編集は対象外です。

## 技術方針

VvvebJsではなく、`iframe + contenteditable + DOM API` を採用しています。今回の目的に不要なページビルダー機能を避け、SingleFile HTMLのDOMを直接扱い、出力内容を管理しやすくするためです。詳しい比較と受入条件は `docs/02-poc-implementation-specification.md` を参照してください。

PoC確認後の優先課題と実運用への進め方は `docs/03-pilot-and-production-plan.md` を参照してください。
