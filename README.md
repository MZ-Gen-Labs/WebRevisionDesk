# Web Revision Desk

既存Webページを取り込み、見た目を確認しながら編集し、修正後HTML、視覚的な赤入れ、修正指示を作成するデスクトップ向けローカルWebアプリです。

[![CI](https://github.com/MZ-Gen-Labs/WebRevisionDesk/actions/workflows/ci.yml/badge.svg)](https://github.com/MZ-Gen-Labs/WebRevisionDesk/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

SingleFileを使わず、URLを取得用Chromiumで開いて現在の表示を単一HTMLとして取り込む機能も備えています。この取得機能はApache-2.0のPlaywrightと本プロジェクト独自コードで構成しています。

## できること

- ローカルHTMLの読込とsandbox内プレビュー
- ページ内要素の選択、テキスト編集
- リンクURL、画像、alt、CSS classの変更
- 要素の削除と同一親内での前後移動
- 選択した既存ブロックの複製
- 編集操作の変更履歴表示
- 変更前後をまとめた差分・修正指示HTMLの出力
- 元ページの見た目に取消し線・追加色・変更ラベルを重ねた赤入れHTMLの出力
- 修正前/修正後の切替と読込時点へのリセット
- 操作単位のUndo/Redo（ボタンおよびCtrl/Cmd+Z）
- `modified.html` のダウンロード
- 修正前・修正後・差分・赤入れ・案件情報のZIP一括保存
- 基準URL配下の複数ページを案件フォルダで階層管理
- 「取り込む・修正する・確認して保存」の3段階案内
- 選択した要素に必要な項目だけを表示する初心者向け編集メニュー
- 未保存状態の表示と、未保存のまま画面を閉じる際の警告

## 起動方法

Node.js 20以降を用意し、このフォルダーで次を実行します。

```bash
npm install
npx playwright install chromium
npm run dev
```

表示されたローカルURLをChromeまたはEdgeで開きます。最初の確認には `test-data/sample.html` を使用できます。

## テスト

依存モジュール更新後を含む通常の確認は、Chromiumをインストールしたうえで次を実行します。

```bash
npx playwright install chromium
npm test
```

`npm test` は、URL階層・Windowsファイル名・更新判定・SHA-256拒否等の単体テスト、本番ビルド、HTML読込・編集・Undo/Redo・ZIP出力・詳細設定のブラウザテストを順に実行します。GitHub ActionsでもPull Requestと`main`へのpushごとに同じ主要テストを実行します。Windows Releaseでは生成した完全版ZIPを展開し、必須ファイルとサーバー起動を追加確認します。

## 操作方法

URL取得・案件選択・ログインは「取り込み・案件設定」を開いて操作します。ページ読込後はこの設定欄が自動で閉じ、編集領域が画面の残りの高さまで広がります。必要なときは見出しを押して再表示できます。案件保存・修正前後・Undo/Redo・共有用保存は上部に常時表示します。

1. 「HTMLを読み込む」からSingleFileで保存したHTMLを選ぶ
2. 画面上部の3段階案内に従い、ページ上の直したい要素をクリックする
3. 右側の「編集メニュー」に表示された項目から内容を変更する
4. 文章はページ上でダブルクリックして直接編集することもできる
5. 「修正前」「修正後」で表示を比較する
6. 「共有用ファイル一式を保存」で提出・保管用ZIPを出力する
7. 修正後ページ、修正内容一覧、変更箇所ページだけが必要な場合は「その他の保存」から選ぶ

「1つ戻す」「やり直す」で編集操作を段階的に戻せます。「すべてリセット」は全変更を読み込み時点へ戻します。
通常は文章・リンク・画像差し替えだけが表示されます。画像のaltやCSS classを変更する場合は「詳細設定を表示」を有効にします。読込・変更後は「案件フォルダへ未保存」と表示され、案件フォルダへ保存すると「保存済み」になります。ZIPやHTMLのダウンロードでは案件フォルダへの保存状態は変わりません。

## 案件フォルダで複数ページを管理

1. ChromeまたはEdgeで「案件フォルダを選択」を押す
2. 新規または既存の案件フォルダを選択する
3. 案件名と基準URLを入力する
4. 「関連ページを探す」を押す
5. 左側に表示された「未取得」ページを選ぶ
6. 取得用ブラウザでページを確認し「表示中ページを取り込む」を押す
7. 編集後に「案件フォルダに保存」を押す
8. 「保存済み」になったページは左側一覧から編集状態を再度開ける

一括検索は基準URLと同じドメインかつ配下パスだけを再帰的にたどり、アンカー違い・追跡用クエリ等を正規化して重複を除外します。画像、PDF、動画、ZIP等はページ候補に含めません。1回の検索は最大100ページで停止します。ログインや画面操作が必要なページは、一覧から選んで取得用ブラウザを開いた後に操作できます。

基準URLが `https://example.com/products/widget` の場合、ページは次のように保存されます。

```text
案件フォルダ/
├── project.json
└── pages/products/widget/
    ├── index/
    │   ├── original.html
    │   ├── working.html
    │   ├── modified.html
    │   ├── diff.html
    │   ├── redline.html
    │   └── page.json
    └── function_const_01/
        └── ...
```

フォルダ名にはWindows 11で利用可能な文字だけを使用し、`project.json` と `page.json` のパスはOSに依存しない相対パスで記録します。編集途中の状態は `working.html`、提出可能な修正後ページは `modified.html` です。ページを切り替える際は未保存のページを案件フォルダへ自動保存します。

一括検索は、自身または所属組織が取得を許可されているサイトに対して使用してください。

### 一括取得と公開ページの更新確認

- 左側のチェックボックスで複数ページを選択する
- 「選択を一括取得」で未取得ページを順番に取得・保存する
- 未取得ページの本体をクリックすると、そのページを直接取り込んで中央の編集画面に表示し、案件フォルダへ保存する
- ログインや画面操作が必要なページは、一覧下の「取得用ブラウザで開く」から確認後に取り込む
- 保存済みページを選び「選択を更新確認」で公開中ページとの差を確認する
- 「選択を未取得へ戻す」で、選択した保存済みページの原本・編集内容・差分・履歴・旧版を削除する。URLは一覧に残るため再取得できる
- 緑の「公開版と同じ」は取得時点と同じ状態
- オレンジの「公開版に更新あり」はテキスト、リンク、画像、構造、CSSのいずれかに差がある状態
- 「上書きしない」で案件内の編集を維持する
- 「バックアップして更新」で現在の一式を `versions/` へ退避してから公開版へ置き換える

更新確認だけでは `original.html` や編集中の内容を上書きしません。上書きを選択した場合も旧版はページフォルダ内の `versions/<日時>/` に保存されます。一括処理は同じログインプロファイルを使い、サーバー負荷を抑えるため1ページずつ順番に実行します。リセットは削除確認後に実行され、選択したページ自身の保存ファイルだけを対象とするため、URL階層上の子ページは保持されます。

## URLから取り込む

1. WebページURLを入力する
2. 「取得用ブラウザを開く」を押す
3. 開いたChromiumで必要に応じてログイン、スクロール、タブ展開等を行う
4. 編集画面へ戻り「表示中ページを取り込む」を押す
5. CSS・画像等の埋め込み後、そのまま編集を開始する

取得用ブラウザのログイン状態はアプリ本体とは別のユーザーデータ領域に保存され、外部サービスへは送信されません。Windowsでは通常 `%LOCALAPPDATA%\WebRevisionEditor\capture-profile` です。共有PCでは利用後のプロファイル管理に注意してください。

## アプリの設定と更新確認

### ログインが必要なページの取得準備

案件の基準URL（案件未選択時はWebページURL）を入力し、「このサイトはログインが必要」を有効にします。「ログイン用ブラウザを開く」で表示したブラウザ内でログイン・多要素認証を済ませ、対象ページを閲覧できることを確認してから、編集画面の「ログイン完了」を押してください。待機中は関連ページ検索、一括取得、公開ページ更新確認を開始できません。「ログイン待機を中止」で待機を取り消せます。

スイッチは選択中の案件へ保存されます。完了状態は画面を開いている間だけ保持し、案件の切り替えやURLの手入力変更で再確認待ちに戻ります。ログイン成功や期限切れの自動判定は行いません。認証が切れた場合は再度ログイン用ブラウザを開いてください。

完了時にブラウザを閉じ、専用プロファイルに残るCookie等を後続処理で使用します。ブラウザ終了時に失効する認証やsessionStorageのみを使うサイトでは、一括処理に認証を引き継げない場合があります。その場合は取得用ブラウザでログイン後、そのまま「表示中ページを取り込む」を利用してください。待機の中止はログアウトや認証情報の消去ではありません。専用プロファイルは案件間で共通です。

### 更新確認

画面左上のバージョン表示を押すと、アプリ更新パネルが開きます。公開後のGitHubリポジトリURLを登録すると、GitHub Releasesの最新版を起動時または手動で確認できます。

- 設定とログイン用ブラウザ情報はアプリ本体の外へ保存されるため、新しいZIPへ入れ替えても引き継がれます
- 最新ReleaseにWindows用ZIPが添付されている場合、更新パネルからダウンロードできます
- GitHubが返すSHA-256ダイジェストを必須とし、欠落・不一致の場合は更新ZIPを拒否します。自動更新にはWindows x64の更新専用ZIPを使用し、完全版や他OS用ZIPは選択しません
- Releaseへ `update.json` を添付すると、セキュリティ更新・重要度・必須更新を画面に表示できます
- ダウンロード済みZIPはユーザーデータ領域の `updates/<バージョン>/` に保存されます

`update.json` の例：

```json
{
  "version": "1.0.2",
  "updateType": "security",
  "severity": "high",
  "mandatory": false,
  "minimumSupportedVersion": "1.0.0",
  "notes": "依存モジュールの脆弱性を修正しました。"
}
```

Windowsポータブル版では、ダウンロード後に「再起動して更新を適用」を押すと更新用ランチャーが新しいバージョンを別フォルダへ展開して切り替えます。新バージョンが起動確認に失敗した場合は、`current.json` を旧版へ戻して自動的にロールバックします。開発版からは誤適用を防ぐため自動切り替えできません。

## Windowsポータブル版の作成

Windows 11またはWindowsのCI環境で次を実行します。

```powershell
npm ci
npm run build:portable
```

`release/` に次が生成されます。

- `WebRevisionDesk-<version>-win-x64-complete.zip`：初回配布用
- `WebRevisionDesk-<version>-win-x64.zip`：アプリ内更新用
- `update.json`：GitHub Releaseへ添付する更新種別情報
- `SHA256SUMS.txt`：配布物のSHA-256

初回配布用ZIPを展開し、`Start-WebRevisionDesk.cmd` を実行すると起動します。GitHub Releaseにはアプリ内更新用ZIP、`update.json`、`SHA256SUMS.txt`を添付します。完全版ZIPは初回利用者向けです。

## 安全性と制約

編集プレビューはsandbox付きiframeに表示し、入力HTMLのスクリプト、フォーム送信、ポップアップを許可しません。URL取得ではCSS、CSS内の追加CSS、画像等を可能な範囲で単一HTMLへ埋め込みます。取得後も外部URLが残るページでは通信が発生する可能性があります。

ブラウザでHTMLを再解析するため、属性順序や空白等は元ファイルと同一にならない場合があります。iframe、Shadow DOM、canvas、疑似要素、JavaScriptが再生成する内容の編集は対象外です。

## 技術方針

VvvebJsではなく、`iframe + contenteditable + DOM API` を採用しています。今回の目的に不要なページビルダー機能を避け、SingleFile HTMLのDOMを直接扱い、出力内容を管理しやすくするためです。詳しい比較と受入条件は `docs/02-poc-implementation-specification.md` を参照してください。

PoC確認後の優先課題と実運用への進め方は `docs/03-pilot-and-production-plan.md` を参照してください。
